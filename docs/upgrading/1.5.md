# Upgrading to 1.5

Version 1.5 has one breaking change. It only affects stores that use `typeAccessor`.

---

## Type streams are named `types/<type>`

`typeAccessor` maintains one stream per event type. These streams are now named `types/<type>`, the same way `tagsAccessor` names its streams `tags/<tag>`. Before, a type stream had the bare type name, so an event type `order` and a regular stream `order` shared one name.

```js
// Before (1.4)
store.query(['CourseCreated', 'CourseCapacityChanged']);
store.getEventStream('CourseCreated');

// After (1.5)
store.query(['types/CourseCreated', 'types/CourseCapacityChanged']);
store.getEventStream('types/CourseCreated');
```

A `DcbQuery` names types without the prefix and needs no change:

```js
store.query({ items: [{ types: ['CourseCreated'], tags: ['course/jdsj4'] }] });
```

### Automatic migration

The first time a writer opens a store from an earlier version, it moves every existing type stream to its new name:

- It only moves streams that `typeAccessor` created, recognized by their stored matcher. A regular stream that happens to have a type's name stays where it is.
- It copies the index entries into the new stream and deletes the old one. No documents are read or rewritten, so this is fast even for large stores.
- It emits `'stream-migrated'` with the old and the new name for each moved stream.

A read-only store does not migrate. Open the store once with a writer on 1.5 before you start read-only instances on 1.5, otherwise they still see the old stream names.

**Action required:**

- Prefix type stream names with `types/` wherever you name them directly: selectors for `query()` and `fromStreams()`, `getEventStream()`, and `getStreamVersion()`.
- Consumers keep their state per stream name, so a consumer on `types/<type>` starts at position 0. The migrated stream has the same entries in the same order, so if you need to keep a consumer's progress, copy its position from the old consumer to the new one.
- A commit condition captured by a 1.4 process names the old streams. Do not carry such conditions across the upgrade; query again after the writer has migrated.
- If you used `streamSources` with `{ path: 'type', nameBuilder: (v) => v }` to keep bare names, nothing is migrated and nothing changes for you.
