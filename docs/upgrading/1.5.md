# Upgrading to 1.5

Version 1.5 changes the low-level `Index` API and the default lock handling. Code that only uses `EventStore`, `EventStream` and `Consumer` is not affected by the `Index` changes.

---

## 1. `Index.range()` returns a lazy iterator

`Index.range(from, until)` now returns an iterator instead of an array, and `Index.all()` returns the same kind of iterator over all entries.

- `from > until` iterates backwards instead of returning `false`.
- Out of bounds positions give an empty iteration instead of `false`.
- One entry object is reused for the whole iteration. Read its fields before advancing, and copy what you need to keep.
- `Index.validRange()` is removed.
- `union()` and `intersect()` in `utils/indexUtil.js` combine two such ranges lazily instead of entry arrays.
- `Index.get()` still returns an entry object, but creates a new one on each call, so the same position no longer returns the identical object twice.

```js
// Before (1.4)
const entries = index.range(1, 10) || [];
entries.forEach(entry => handle(entry));

// After (1.5)
for (const entry of index.range(1, 10)) {
    handle(entry);
}
// or, if you need an array of independent entries
const entries = Array.from(index.range(1, 10), ({ number, position, size, partition }) => ({ number, position, size, partition }));
```

**Action required:** Replace array access on the result of `range()` with iteration, remove `false` checks and calls to `validRange()`, and do not keep references to iterated entries. Compare entries from `get()` by their fields, not by identity.

---

## 2. A stale lock is reclaimed automatically

The default `lock` option is now `LOCK_AUTO`. If the process that holds the storage lock is no longer running on the same machine, a writer reclaims the lock and repairs the store on open. Before, it threw `StorageLockedError` and you had to open the store with `LOCK_RECLAIM`.

A lock held by a running process, or by a process on another machine, still throws `StorageLockedError`, which now names the lock holder.

**Action required:** None in most setups. If you rely on the exception after a crash, for example to repair the store manually, set `lock: LOCK_THROW`.

---

## 3. Partition names ending in `~<number>` are reserved

Partitions whose names hash to the same partition id are now stored in separate files with a `~<n>` suffix. Creating a new partition whose name ends in `~` followed by a number (e.g. a stream `orders~2` with the default partitioner) throws.

**Action required:** Rename such streams, or change your `partitioner` so it does not produce these names. Existing partitions with such names can still be opened.
