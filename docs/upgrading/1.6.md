# Upgrading to 1.6

## Projections read from an event source

Decision models and read models no longer take the store but an event source, and reading is async. This lets the same projections run against a store in the same process or behind the HTTP API.

```js
// Before (1.5)
import { buildDecisionModel } from 'event-storage/projections';

const model = buildDecisionModel(store, { capacity: CourseCapacity(courseId) });
const updated = model.update();
for (const event of model.since()) { /* ... */ }

// After (1.6)
import { localSource } from 'event-storage';
import { buildDecisionModel } from 'event-storage/projections';

const source = localSource(store);
const model = await buildDecisionModel(source, { capacity: CourseCapacity(courseId) });
const updated = await model.update();
for await (const { event } of model.since()) { /* ... */ }
```

**Action required:**

- Create the source once with `localSource(store)` and pass it to `buildDecisionModel()`. Over HTTP, use `httpSource(client)` from `event-storage-http/client`.
- `await` `buildDecisionModel()`, `model.update()` and `readModel.decisionModel()`. Command handlers that build a decision model become async.
- `model.since()` is an async iterable of `{ event, metadata, position, type, tags }` instead of an `EventStream`.
- Committing is unchanged: pass `model.commitCondition` to `store.commit()`.
