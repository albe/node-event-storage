# Upgrading to 1.6

## Read errors reach the reader

An `EventStream` used to end silently when reading failed, so a read that a `preRead` hook rejected looked like an empty stream. Errors now reach the reader:

- Iterating (`for...of`, `.events`, `forEach()`, `next()`) throws the error.
- A piped or `'data'`-consumed stream emits it as `'error'`.

A range outside the stream, e.g. reading from beyond the end, is still empty and does not throw.

```js
// Before (1.5): a rejected read returned no events
const events = store.getEventStream('admin-stream').events; // []

// After (1.6)
try {
    const events = store.getEventStream('admin-stream').events;
} catch (error) {
    // e.g. 'Not authorized to read from this stream' from the preRead hook
}
```

**Action required:**

- Catch errors where a `preRead` hook can reject a read, and where matcher functions can throw.
- Listen for `'error'` on streams that are piped or read through `'data'`.
