# Upgrading to 1.4

Version 1.4 has two breaking changes. Both only affect stores that use `fromStreams()` / `query()` with missing streams or a function `typeAccessor`.

---

## 1. Missing streams no longer throw

`fromStreams()` and `query()` treat streams that do not exist as empty instead of throwing.

- In an `OR` group a missing stream has no effect.
- In an `AND` group a missing stream makes that branch yield nothing.

**Action required:** If you relied on the exception to detect a missing stream, check explicitly with `eventstore.getStreamVersion(name) === -1` or `name in eventstore.streams`.

---

## 2. `typeAccessor` must be a string path

`typeAccessor` only accepts a dot-notation path into the event payload; passing a function throws in the constructor.

```js
// Before (1.2 / 1.3)
new EventStore('my-store', { typeAccessor: (event) => event.type });

// After (1.4)
new EventStore('my-store', { typeAccessor: 'type' });
```

If you need custom stream names derived from a payload value, use `streamSources`:

```js
new EventStore('my-store', {
    streamSources: [
        { path: 'type', nameBuilder: (value) => `type/${value.toLowerCase()}` }
    ]
});
```

Note that only `typeAccessor` and `tagsAccessor` are used to resolve `types` and `tags` in a `DcbQuery`.
